# Phase 2: Reproducible Feature Engineering Pipeline

## 1. Pipeline architecture

```text
recovery_dataset_v1.csv
  -> raw feature validation
  -> deterministic feature transformation
  -> recovery_features_v1.csv
```

The pipeline is standalone and offline. It does not train a model, call the application runtime, or modify the raw historical dataset.

## 2. Input features

The pipeline maps the raw dataset columns to the approved 6.1.2 feature names:

- `transaction_amount`
- `currency`
- `payment_method` -> `payment_method_attempted`
- `failure_category`
- `failure_reason_present` -> `has_failure_reason`
- `attempt_number`
- `prior_failed_attempt_count`
- `prior_temporary_failure_count`
- `candidate_action` -> `candidate_action_type`

Target, outcome, identifiers, and post-decision fields are excluded.

## 3. Transformations

Numeric features use deterministic numeric passthrough. No scaling is applied because the first pipeline does not require a learned transform and the feature contract permits numeric values directly.

`has_failure_reason` is converted to integer `0` or `1`.

Categorical features use fixed one-hot encoding with category order taken from the approved Phase 1 enums.

The model-ready matrix has 19 columns:

```text
transaction_amount
attempt_number
prior_failed_attempt_count
prior_temporary_failure_count
has_failure_reason
currency__INR
currency__USD
currency__AED
payment_method_attempted__UPI
payment_method_attempted__CARD
payment_method_attempted__NET_BANKING
failure_category__TEMPORARY_FAILURE
failure_category__PAYMENT_METHOD_FAILURE
failure_category__CUSTOMER_ACTION_REQUIRED
failure_category__UNKNOWN_FAILURE
candidate_action_type__RETRY
candidate_action_type__ALTERNATE_METHOD
candidate_action_type__CUSTOMER_ACTION
candidate_action_type__ESCALATE
```

## 4. Encoding strategy

One-hot columns are emitted in the fixed schema order. `candidate_action_type` remains explicit, so one payment context can be transformed separately for each candidate action.

## 5. Missing-value handling

Missing numeric values become `0`. Missing booleans become `0`. Missing categorical values are treated as unknown and produce zero in all known-category columns.

Rows are never silently dropped.

## 6. Unknown-category handling

Unknown categorical values use the explicit policy `__UNKNOWN__`. The current compact matrix does not add an unknown column; instead, all known-category columns for that feature are `0`. The schema artifact records this policy for future inference implementations.

## 7. Feature ordering

Feature ordering is defined by `recovery_features_v1.schema.json`. Every output row is constructed by iterating that exact list, and validation rejects any ordering mismatch.

## 8. Versioning

- Feature pipeline version: `1.0.0`
- Feature schema version: `6.3.1`
- Source dataset: `recovery_dataset_v1.csv`

The pipeline version changes when transformation behavior changes. The schema version changes when feature names, ordering, or representations change.

## 9. Training/inference separation

`fitFeaturePipeline(trainingRows)` accepts training rows and returns the fixed schema. No parameters are learned from validation or test data, and no full-dataset statistics are fitted. The same schema can be passed to `transformRows` during future inference.

If learned scaling or other data-dependent transformations are added later, fitting must happen only on the training partition.

## 10. Validation

Run from `backend/`:

```bash
node src/intelligence/generate-recovery-features.js
```

The pipeline validates source columns, numeric/boolean input values, output numeric values, deterministic ordering, and output row count. It does not include target, outcome, decision, transaction, attempt, or execution fields in the matrix.

## 11. Reproducibility

The same raw CSV and feature-pipeline version produce identical feature CSV bytes and schema. The raw dataset remains unchanged. Generated artifacts are:

- `data/phase-2/recovery_features_v1.csv`
- `data/phase-2/recovery_features_v1.schema.json`
- `data/phase-2/recovery_features_v1.metadata.json`

No ML model is trained by this pipeline.
