# Phase 2: Internal Recovery Prediction Service

## 1. Service responsibility

`RecoveryPredictionService` answers one question:

```text
What is the estimated recovery probability for this candidate action?
```

It is an offline/internal reusable service. It does not select an action, execute an action, call the Phase 1 decision engine, or expose an HTTP endpoint.

## 2. Input contract

The single-action method accepts the finalized decision-time fields:

- `transaction_amount`
- `currency`
- `payment_method_attempted`
- `failure_category`
- `has_failure_reason`
- `attempt_number`
- `prior_failed_attempt_count`
- `prior_temporary_failure_count`
- `candidate_action_type`

Missing properties are rejected. Present missing numeric or categorical values follow the finalized feature-pipeline behavior. Invalid actions and malformed numbers are rejected.

## 3. Output contract

`predict(record)` returns:

```json
{
  "candidate_action_type": "RETRY",
  "recovery_probability": 0.82,
  "model_version": "phase2-interaction-logistic-v1",
  "feature_schema_version": "6.3.1",
  "feature_pipeline_version": "1.0.0",
  "predicted_at": "2026-01-01T00:00:00.000Z"
}
```

`recovery_probability` is a probability, not a confidence score, and is guaranteed to be in `[0, 1]` when returned.

## 4. Model loading

The service loads the frozen artifact:

```text
data/phase-2/models/recovery_interaction_v1.model.json
```

Loading happens during service construction. The service never retrains at runtime.

## 5. Feature-pipeline integration

The service converts the canonical inference record to the existing raw feature shape and calls `transformSingleDecisionRecord()`. It then applies the frozen interaction model’s persisted coefficients and training-only scaler parameters. Feature engineering is not duplicated in the service.

## 6. Multi-action prediction

`predictAll(context)` calls the single-action method for each supported action in deterministic order:

```text
RETRY -> ALTERNATE_METHOD -> CUSTOMER_ACTION -> ESCALATE
```

It returns probabilities only. It does not rank, select, recommend, or execute an action.

## 7. Validation

The service validates required fields, supported actions, malformed numeric values, forbidden post-decision fields, model/schema/pipeline compatibility, coefficient shape, and output probability range.

## 8. Error handling

`PredictionServiceError.code` distinguishes failures:

- `INVALID_INPUT`
- `MODEL_NOT_FOUND`
- `SCHEMA_NOT_FOUND`
- `MODEL_LOAD_FAILED`
- `MODEL_SCHEMA_INCOMPATIBLE`
- `PREDICTION_FAILED`
- `INVALID_PREDICTION_OUTPUT`

A failure is thrown clearly. The service does not return a fake probability and does not invoke a recovery action. Fallback routing belongs to the future decision policy.

## 9. Model/version compatibility

The service requires:

- model version `phase2-interaction-logistic-v1`
- feature schema version `6.3.1`
- feature pipeline version `1.0.0`
- model base feature columns equal to the persisted schema columns

## 10. Relationship to Phase 1

The prediction service is advisory-only. Phase 1 remains the live business decision and execution system. This service does not replace `RecoveryDecisionEngine`, alter `RecoveryExecutionService`, or change persistence behavior.

## 11. Responsibility boundary

- Prediction service: estimate probability
- Future decision policy: apply safety rules and select an action
- Recovery execution service: execute the selected action

The service does not select or execute actions.
